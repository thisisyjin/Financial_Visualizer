## Today I Learned - Day 1

### 1. 오늘 구현한 내용 요약
- **Next.js App Router 기본 레이아웃 정리**: `layout.tsx`에서 전역 배경색을 `bg-slate-950`, 텍스트를 `text-slate-50` 베이스로 설정하고, 최소 높이를 `min-h-screen`으로 맞췄다.
- **대시보드 페이지 골격 구성**: `page.tsx`에서 [헤더 - 메인 콘텐츠 - 푸터] 구조를 만들고, 메인 내부에 추후 "입력 폼"과 "차트"가 들어갈 그리드 레이아웃을 잡았다.
- **다크 모드 톤 전역화**: `globals.css`에서 배경/텍스트 CSS 변수를 slate 계열 색상으로 맞추고, 폰트를 시스템 폰트로 정리했다.

### 2. 주요 코드 구조 (`layout.tsx`와 `page.tsx`의 역할 차이)
- **`layout.tsx`**
  - App Router에서 모든 페이지의 공통 뼈대를 담당한다.
  - `html`, `body` 태그를 여기에서 정의하며, 전역 배경색, 텍스트 색, 최소 높이 같은 "사이트 전체 레벨"의 스타일을 설정한다.
  - 메타데이터(`metadata`)를 정의해서 브라우저 탭 타이틀과 페이지 설명을 한 번에 관리한다.
- **`page.tsx`**
  - 특정 경로(`/`)에 대한 실제 화면 구성을 담당한다.
  - 오늘은 이 안에서 헤더(로고 + GitHub 링크), 메인 콘텐츠(입력 폼/차트 자리), 푸터(카피라이트와 기술 스택 텍스트)를 정의했다.
  - 메인 영역에서는 `max-w-7xl` 컨테이너와 그리드를 사용해 이후에 올 폼/차트 컴포넌트를 자연스럽게 끼워넣을 수 있도록 레이아웃을 설계했다.

### 3. 새로 배운 개념
- **Next.js App Router의 폴더 구조 의미**
  - `src/app/layout.tsx`: 해당 라우트 트리 전체에 공통으로 적용되는 루트 레이아웃. 여기서 HTML 문서 구조와 전역 스타일, 메타데이터를 설정한다.
  - `src/app/page.tsx`: 특정 경로의 메인 페이지 컴포넌트. 실제 화면 UI를 담당한다.
  - 같은 디렉터리 내에서 `layout.tsx`는 "껍데기", `page.tsx`는 그 안에 들어가는 "내용물"이라고 이해하면 구조를 잡기가 쉽다.
- **Tailwind와 전역 CSS의 역할 분리**
  - Tailwind 유틸리티 클래스로 컴포넌트별 세부 스타일을 빠르게 잡고,
  - `globals.css`에서는 배경/텍스트 색상, 기본 폰트 등 사이트 전체에 공통으로 적용되는 최소한의 설정만 유지하는 방향이 깔끔하다.
